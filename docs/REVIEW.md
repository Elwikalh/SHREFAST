# Super X — مراجعة وتحديث تقني

## ما تغير

- نقل الواجهة من ملف HTML يحتوي نسخة مجمّعة ثابتة من React وLucide إلى مسار `/wasl` داخل Next.js. مصدر الواجهة القديم مستعاد في `components/wasl/portal.jsx`، وليس إعادة كتابة كاملة؛ أسماء كثير من المتغيرات ما زالت مختصرة وتحتاج إعادة هيكلة تدريجية.
- الصفحة الرئيسية تعرض نفس المنصة مباشرة. الروابط القديمة `/wasl/index.html` تحتفظ بالـhash الذي تختاره البوابات والإطارات المضمّنة.
- الأيقونات تستخدم استيرادات مسماة من `lucide-react` في `components/wasl/icon.jsx`؛ لا تحميل لمكتبة أيقونات كاملة من CDN ولا رسم يدوي بديل لأيقونات الواجهة.
- تحديث المكتبات إلى الإصدارات المستقرة المتاحة من npm وقت التحديث، مع تثبيت أرقام الإصدارات وملف `pnpm-lock.yaml`. TypeScript وESLint وpnpm اختيرت من أحدث الخطوط المتوافقة بدل فرض major جديد يكسر الأدوات.
- بناء Docker يستخدم `--frozen-lockfile` بدل تحميل نسخ متغيرة عند كل نشر.
- عميل الشبكة يوقف الطلبات المعلقة بعد 15 ثانية ويوحد طلبات GET المتزامنة المتطابقة دون توحيد عمليات الكتابة أو تخزين بيانات العملاء في cache.
- إضافة أسماء واضحة لقارئ الشاشة في التنقل، إعلان رسائل الحالة، مؤشر التركيز بلوحة المفاتيح واحترام تقليل الحركة.
- كلمات المرور الجديدة تستخدم scrypt غير المتزامن. الحسابات القديمة تظل قادرة على الدخول، وتتم ترقية التجزئة القديمة بعد دخول ناجح. بيانات التجزئة المشوهة تُرفض دون استثناء timingSafeEqual.
- منع JSON غير الكائنات في واجهات الكتابة؛ تحقق Zod في إنشاء الطلبات يمنع القيم السالبة وغير المحدودة والحقول الضخمة. إجمالي الطلب يظل مبلغًا صحيحًا بالجنيه موافقًا لعمود PostgreSQL الحالي.
- اشتراكات المناديب المدفوعة تفحص تاريخ الانتهاء؛ الحساب الموقوف لا يعمل حتى لو الاشتراك غير مطلوب.
- Webhook واتساب لا يقبل رسائل بدون `WASL_META_APP_SECRET` وتوقيع صحيح. إضافة معرف رسالة المزود وفهرس فريد لمنع تكرار الرسائل عند إعادة المحاولة. فشل قاعدة البيانات يرجع 503 بدل تأكيد نجاح وهمي يفقد الرسالة.
- أكواد دعوة المناديب تستخدم مولد أرقام عشوائية تشفيري بدل Math.random.
- اختبارات Vitest وPlaywright. ملف GitHub Actions أُعد محليًا، لكنه مستبعد من الرفع لأن محاولة رفع الدفعة التي احتوته رُفضت بصلاحيات التوكن الحالية.

## مهم قبل النشر الحقيقي

هذه الدفعة **ليست شهادة أن التطبيق آمن للإنتاج**. بقيت مشاكل سابقة تتطلب تغيير نظام الحسابات وسلوك المنتج:

1. **حرج — المصادقة والصلاحيات:** مسارات الإدارة والإعدادات والطلبات والتسويات وبعض بيانات الأشخاص لا تتحقق من جلسة موثوقة وصلاحية المالك. معرفة مرجع حساب ليست تسجيل دخول. يجب إضافة جلسات فعلية وربط الحساب بالنشاط/الشركة والتحقق من الملكية على الخادم قبل إتاحة بيانات حقيقية. وجود better-auth في dependencies وحده لا يطبق ذلك.
2. **عالٍ — عزل الطلبات:** `GET /api/wasl/orders` القديم يرجع أحدث الطلبات دون تطبيق فلاتر merchant/companyRef التي ترسلها الواجهة. يلزم ربط الطلبات بمراجع الكيانات، وليس الأسماء فقط، ثم فلترة مبنية على الجلسة.
3. **عالٍ — مسار ناقص:** الواجهة تستدعي `/api/wasl/company/assign` لكن المسار غير موجود في الريبو. لا تضف مسار إسناد غير محمي كحل سريع؛ يجب تنفيذه مع الملكية والصلاحيات وانتقالات حالة ذرية تمنع الإسناد المتزامن.
4. **عالٍ — حماية تسجيل الدخول:** ما زالت هناك حاجة إلى rate limiting موزع ومنع محاولات التخمين وإثبات ملكية رقم الهاتف. الحد الأدنى الحالي لكلمة المرور محفوظ للتوافق، وليس سياسة أمان موصى بها.
5. **متوسط — البيانات التجريبية:** بعض البوابات ما زالت تعرض بيانات محاكاة من المصدر السابق. يجب فصل وضع العرض التجريبي عن الإنتاج بوضوح قبل استخدامها لاتخاذ قرارات تشغيلية.
6. **متوسط — قاعدة البيانات:** تهيئة الجداول باستخدام DDL وقت التشغيل ما زالت موجودة. انقلها إلى migrations مُراجعة ومُصدّرة، واختبر نسخة احتياطية/استعادة قبل تطبيقها على البيانات الحقيقية.

## إعداد واختبار

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm --filter @el7bboB/web exec playwright install chromium
pnpm --filter @el7bboB/web test:e2e
```

اختبارات الواجهة تستخدم استجابات API تجريبية ثابتة؛ لا تثبت نجاح التعامل مع PostgreSQL أو عمليات الطلب/الإسناد/تسجيل الدخول على بيئة حقيقية. اختبارات الـWebhook تتحقق من توقيعه وإرسال معرف الرسالة لطبقة التخزين؛ يجب اختبار الفهرس الفريد وإعادة المحاولة فعليًا على PostgreSQL قبل النشر.

للـWebhook، اضبط `WASL_META_APP_SECRET` و`WASL_META_VERIFY_TOKEN` في بيئة التشغيل، وليس في Git. سيضيف أول طلب لطبقة التخزين عمود `message_id` وفهرسه الفريد بشكل غير هدّام؛ راجع صلاحيات DDL وأثر القفل في staging.

لا يتم دمج هذا الفرع أو نشره تلقائيًا ضمن هذه المهمة. استخدم طلب الدمج للمراجعة واختبار staging أولًا.

## تدقيق المكتبات

تم تصحيح esbuild القديم الذي كانت تستخدمه أدوات Drizzle عبر override إلى 0.28.2. أظهر فحص npm أيضًا تحذيرًا عاليًا في `braces` (اعتماد تابع لأدوات ESLint عبر fast-glob/micromatch)، ولم يعرض الفحص إصدارًا مصححًا متاحًا. هذا اعتماد تطوير، وليس منطق واجهات الإنتاج؛ لا تستخدم أدوات glob على أنماط غير موثوقة، وراقب تحديثًا رسميًا. لا ندعي أن التدقيق خالٍ من التحذيرات.

## نتيجة التحقق لهذه الدفعة

- نجح فحص الأنواع وlint وبناء Next.js.
- نجحت 35 حالة اختبار وحدة و10 اختبارات واجهة عبر الكمبيوتر والموبايل.
- فحص اعتماديات الإنتاج لم يبلغ عن ثغرات؛ بقي تحذير braces في اعتماديات التطوير كما موضح أعلاه.
- لم تُجر اختبارات PostgreSQL الفعلية أو نشر Railway، ولم تُدمج التغييرات في main.

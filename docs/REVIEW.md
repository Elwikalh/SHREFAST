# SHARE FAST — تحديث التسجيل والواجهة والمراجعة التقنية

## الواجهة والتسجيل

- `/` صفحة تعريفية عربية RTL جديدة، تستجيب للموبايل والكمبيوتر والوضع الداكن. معاينة التشغيل موسومة «معاينة توضيحية»، بلا شهادات عملاء أو أرقام نجاح غير مثبتة.
- `/register` ثلاث خطوات: نوع الحساب، بياناته، ثم بيانات الدخول. يدعم النشاط التجاري وشركة التوصيل والمندوب، كل محافظات مصر، الصيغ المحلية والدولية والأرقام العربية للهاتف، والتحقق من الحقول وكلمة المرور وتأكيدها والموافقة.
- `/login` دخول حقيقي برقم الهاتف وكلمة المرور ونوع الحساب. `/wasl` لا يعرض بوابة التشغيل دون جلسة؛ تغيير hash أو localStorage لا يغير صلاحيات الخادم. `/wasl/index.html` يحوّل للمسار الجديد.
- الأيقونات باستيرادات مسماة من `lucide-react`. تصميم الصفحة الجديدة منفصل عن مصدر البوابات القديم المستعاد من bundle؛ المصدر القديم ما زال يحتاج إعادة هيكلة تدريجية.

## المصادقة والعزل المنفّذان

- كلمات المرور تستخدم scrypt غير المتزامن. حد التسجيل الجديد 10 أحرف، وحد الدخول يسمح بكلمات الحسابات القديمة للتحويل بعد التحقق منها.
- جلسات opaque عشوائية 256-bit؛ قاعدة البيانات تحفظ SHA-256 للرمز فقط. Cookie: HttpOnly / SameSite=Lax / Secure و`__Host-` في الإنتاج. خروج الحساب يلغي الجلسة في الخادم. الجلسة تنتهي بعد 30 يومًا.
- حماية origin لعمليات الكتابة، JSON متدفق بحد 64KB، وتحديد محاولات موزع في PostgreSQL للهاتف ولـIP، بما فيها أكواد انضمام المناديب. لا تُعاد كلمات المرور أو رموز الجلسات أو الرقم القومي عبر بيانات الحساب العامة.
- مسارات الإدارة والإعدادات والكيانات والطلبات والمناديب والتسويات والدعوات والشراكات تتحقق من الجلسة والملكية. مرجع الحساب أو اسم النشاط ليس credential.
- الطلبات مرتبطة بـmerchant_ref / company_ref / courier_ref، وتُفلتر بهوية الخادم. إنشاء الطلب يشتق اسم النشاط وعنوانه من الجلسة ويحل الشركة قبل عملية INSERT واحدة.
- أُضيف مسار `/api/wasl/company/assign` الناقص: مندوب نشط تابع للشركة، وملكية الطلب أو عقد عميل مقبول، وتحديث ذري للطلب الذي لم يُسند. انتقالات الحالات تمنع القفز للتسليم أو الإسناد المتكرر، ومندوب لا يستطيع تحديث طلب غير مسند له. أهلية الاشتراك المدفوع تفحص في الخادم أيضًا.
- التسجيل لا يثبت ملكية الهاتف. قراءة/قبول دعوات مبنية على الهاتف ممنوع لحساب غير موثّق (`phone_verification_required`). تخزين وقت ونسخة موافقة التسجيل مستقل عن حالة توثيق الهاتف.
- السجلات التجارية القديمة بلا كلمة مرور لا تُستولى عليها بمجرد معرفة الهاتف. حساب المندوب القديم ينتقل فقط بعد إثبات كلمة المرور القديمة. لا يوجد تسجيل إدارة عام.
- Webhook واتساب يتطلب secret وتوقيعًا صحيحًا، مع dedup بمعرف الرسالة؛ فشل التخزين يرجع 503. أكواد الدعوات عشوائية تشفيريًا.

## فحوص الجودة

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm --filter @el7bboB/web exec playwright install chromium
pnpm --filter @el7bboB/web test:e2e
```

- اختبارات وحدات + integration على محرك PostgreSQL مضمّن (PGlite)، تغطي التسجيل والدخول والإلغاء وانتهاء الجلسة والتكرار وrollback وعزل الملكية والإسناد وانتقالات الحالة ورفض دعوات الهاتف غير الموثّق. هذه ليست اختبارًا على قاعدة Railway الحقيقية.
- اختبارات Playwright على الكمبيوتر والموبايل تستخدم API fixtures لاختبار الواجهة: الحقول، الأخطاء، التسجيل، منع الإرسال المزدوج، الروابط القديمة وحماية البوابات. لا تختلط بادعاء أن API mocks تثبت الخادم.
- Docker يوقف البناء إذا فشل lint أو اختبارات الخادم، وفحص الأنواع بعد بناء Next.js. ملف lock ثابت و`--frozen-lockfile` في البناء.
- فحص GitHub Actions الكامل مُعد في `docs/ci-workflow.yml`. رفض GitHub الكتابة إلى `.github/workflows/ci.yml` برسالة **403 Resource not accessible by personal access token** عبر اتصالي GitHub، حتى بعد تحديث الاتصال. لا نعتبر السبب صيغة YAML، ولا نثبت من الرسالة وحدها إعداد التوكن الدقيق. نقل الملف للمسار المطلوب يحتاج اتصالًا يسمح بهذه العملية أو رفعًا من واجهة GitHub بواسطة مالك الريبو. وجوده في docs لا يفعّل Actions.

## المطلوب قبل الإطلاق العام

1. **Staging ونسخة احتياطية:** تحقق من متغيرات Railway وصلاحيات DDL على نسخة احتياطية؛ جداول wasl ما زالت تستخدم تهيئة lazy وقت التشغيل، وليس migrations مُصدَّرة. اختبر ترقية/استعادة البيانات قبل main.
2. **الهوية والاسترجاع:** لا مزود SMS/OTP أو استرجاع كلمة مرور متصل. لا يوجد زر وهمي يرسل كودًا. تحقّق إداري موثق أو مزود فعلي مطلوب لإثبات الهاتف وربط السجلات القديمة؛ لا تضبط phone_verified_at بسبب تصريح صاحب الحساب فقط. المسؤول يمنح دور admin من وصول DB موثوق بعد تحقق، وليس API تسجيل عامًا.
3. **البيانات القديمة:** الطلبات السابقة التي لا تحمل مراجع ملكية لا تظهر تلقائيًا للحسابات الجديدة. يجب ربطها بمراجع موثوقة بعد المراجعة، لا بالأسماء غير الفريدة. لا نغيّر ملكية البيانات القديمة تلقائيًا.
4. **تقارير المصدر القديم:** أزيلت طلبات ومناديب البداية التجريبية من حالة التشغيل الأساسية. بعض تقارير الإدارة والشركة ما زالت تحمل بيانات عرض؛ توجد رسالة مراجعة واضحة. يلزم استبدالها قبل اعتماد تقارير مالية فعلية.
5. **الخصوصية:** صفحة بيانات التسجيل توضح الوضع التقني فقط. يلزم للمشغّل سياسة معتمدة وبيانات تواصل واحتفاظ/حذف وحماية إضافية لبيانات الهوية القومية.
6. **التكاملات:** لا يُدّعى أن واتساب أو الدفع أو الخرائط أو تتبع الموقع متصل فعليًا دون إعداد مزوده واختباره.
7. **الأمان التشغيلي:** راجع trusted proxy/IP headers ومراقبة إساءة الاستخدام، تنظيف الجلسات، وإدارة الأسرار. عدم وجود أخطاء في الاختبارات ليس شهادة أمان شاملة.

## نطاق التسليم

التغييرات في فرع مراجعة وPR #2؛ لا دمج تلقائي ولا نشر Railway ضمن هذه الدفعة. نجاح البناء محليًا لا يعني تغيير الموقع الحي. أحدث إصدارات المكتبات المتوافقة مثبتة؛ TypeScript/ESLint لا يُرفَعان إلى major غير متوافق لمجرد رقم أكبر. تحذيرات تدقيق اعتماديات التطوير تراجع منفصلة عن الإنتاج؛ لا ندعي تدقيقًا خاليًا قبل مراجعة النتيجة الحالية.

## نتائج التحقق المحلية

- install frozen، lint، typecheck وبناء Next.js نجحت.
- 54 اختبار وحدة/integration نجحت؛ 26 اختبار متصفح نجحت عبر الكمبيوتر والموبايل؛ طلبات API في فحص الواجهة مُحاكاة.
- تدقيق الإنتاج: صفر ثغرات مبلغ عنها وقت الفحص. اعتماديات التطوير: تحذير high واحد في braces ضمن سلسلة ESLint؛ الفحص لا يعرض إصدارًا مصححًا متاحًا (`patched_versions: <0.0.0`). لا تستخدم أنماط glob غير موثوقة في أدوات التطوير.
- مراجعة بصرية تمت على Landing والتسجيل بكل أدواره والدخول والخصوصية وحالات الأخطاء، على الكمبيوتر والموبايل، مع معاينة الوضع الداكن.
- لم يُبنَ Docker أو يُختبر اتصال Railway الفعلي أو تُدمج main.

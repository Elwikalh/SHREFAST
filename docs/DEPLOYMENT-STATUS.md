# نسخة نشر مع بقاء الربط غير مفعل

المالك طلب نشر العمل المنجز لعرض الشاشات؛ هذه ليست موافقة على حذف Super X أو تشغيل مسار مندوب غير مكتمل.

- لا تغيير لمفاتيح الربط/السياسة أو هوية الحساب أو تسعيرات الإنتاج. لا حذف للقديم ولا إنشاء طلب تجربة في الإنتاج.
- شير: تم تنزيل رأس فرع العمل واختبار البناء الكامل. أصلحت أخطاء lint للواجهات وأنواع fixtures الاختبار، بدون إلغاء قواعد الفحص العامة أو تجاوز فحص أنواع الإنتاج. نجح lint و184 اختبارًا في 19 ملفًا وNext production build وtypecheck للمشاريع الثلاثة.
- الحبوب: نجحت الاختبارات المحلية السابقة وفحص خادم أكثر صرامة مع noUncheckedIndexedAccess/noUnused؛ لا ادعاء ببناء كامل للريبو الخاص في هذه البيئة. استبعدت ملفات tests من tsconfig إنتاج الحبوب لأنها تستعمل حزم اختبار غير موجودة في dependencies الخاصة به؛ لم أحذف الاختبارات أو أعطل فحص أنواع كود الإنتاج.
- يحتاج نجاح نشر Railway إلى فحص فعلي بعد دمج main؛ الدمج وحده لا يثبت تشغيل النسخة.

## الشاشات بعد نجاح النشر
- الحبوب `/staff/admin/preparation`: إعدادات تقدير التجهيز، بصلاحية أدمن الحبوب. لا تشغل الربط.
- الحبوب `/staff/delivery-requests`: عند بقاء provider legacy يبقى المسار القديم/تاريخه ولا تنشئ طلب شير جديدًا؛ ظهور المسار لا يثبت تشغيل شير.
- شير `/wasl/delivery-pricing`: شاشة التسعير، قراءة/تعديل الإعدادات لأدمن المنصة فقط. حساب المطعم لا يملك الصلاحية. لا تحفظ إعدادات تجريبية على الإنتاج.
- شير `/wasl/owned-restaurants`: إدارة السياسة للفروع، بصلاحية أدمن المنصة؛ السياسة غير مفعلة افتراضيًا.
- شير `/wasl`: قائمة انتظار ضمن صلاحيات الحساب؛ لا إسناد تلقائي/قبول مندوب ولا كشف بيانات جميع العملاء.

مسار المندوب الحر وإشعارات الخلفية والفوترة واختبار دورة الربط الكاملة تبقى نواقص قبل التحويل. تعليمات عدم الدمج في ملفات التحضير الأقدم تصف المرحلة السابقة؛ هذا التحديث يسمح بنشر الكود المنجز فقط مع بقاء الربط معطلاً، وليس تشغيله أو حذف القديم. راجع `START-HERE-SHAREFAST.md` للنواقص و`SHAREFAST-BRIDGE.md` لعقد التشغيل وخطة الرجوع.
